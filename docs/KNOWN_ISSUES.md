# 已知问题与排查

## 连续监控约两小时后出现 HTTP 541

**状态：尚未解决，根因未确认。**

用户反馈：Windows 程序持续监控约两小时后，再次收到 HTTP 541，程序进入保护暂停；这次具体在用版本、商品数量和间隔设置尚待确认。当前仓库版本为 v4.0.1。早期浏览器版本也出现过约 60 秒循环运行两小时后受阻，并伴随官网附近门店查询入口消失的反馈。这些现象尚未通过受影响会话的完整诊断建立确定因果关系。

目前不能断言原因是查询频率、官网会话失效、桌面浏览器兼容性，或 Apple 服务端策略。更换提示文字、清除暂停标记或反复自动重试，都不能证明问题得到修复。

### v4.0.1 已处理的范围

- 首次连接时不把页面加载完成直接当作门店服务已准备好。
- 被动观察程序内官网窗口的主页面和门店响应，未就绪或已受阻时不追加监控请求。
- 单次连接或恢复验证只查询一款商品，同款所选门店合并。
- 导出诊断包含近期响应状态、类型、时间和监控请求计数，帮助区分官网自身受阻与程序查询失败。
- 保留 541 后的持久暂停保护；重启、冷却到期和页面重新打开不会自动解除。

这些改动改善了初始化、故障保护和诊断，**没有证明或实现长时间监控 541 的根治**。183 项模块测试及 11 项 EXE 离线检查使用模拟响应，不能用于证明 Apple 服务器在实际会话中稳定可用。

### 遇到问题时

1. 保持监控暂停，记录程序版本、运行多久后出现、商品数量和检查间隔。
2. 在程序内“打开 Apple 官网”，确认官网自己的附近门店查询是否可用。普通 Chrome / Edge 的会话与程序独立，其结果请分开说明。
3. 点击“导出诊断”，保存 JSON。请勿上传整个 `Data` 文件夹、Cookie、登录会话或 Bark 密钥。
4. 官网手动门店查询恢复后，再点击“连接官网，单次验证”。成功后仍需手动开始监控；若继续受阻，保持暂停并提交诊断。

暂停和低频查询可以减少追加请求，但目前没有经过验证、能保证永不出现 541 的频率或运行方式。

### 后续验收要求

- 对照同一故障时段，分别确认官网自带查询和程序查询的响应。
- 根据脱敏诊断明确触发阶段和原因，再实现对应修复。
- 在真实会话中进行超过已知约两小时故障窗口的连续运行，并记录请求量、状态及恢复结果。
- 复测重启、休眠、网络中断后不会重复查询或绕过暂停；保留现有离线回归检查。

## 其他验证边界

- 商品目录是随版本保存的核验快照，官网型号、SKU、页面结构及门店服务可能变化。
- Bark 默认关闭；服务器接收推送不代表手机实际收到，需用户自行验证。
- 可选购物袋准备默认关闭；真实页面兼容性未作长期保证，不包含自动登录、验证码处理、付款或最终下单。
